# ADR-006 — Entry types and serialization

## Status

Accepted.

## Decision

An `Entry` contains its identifier, name, timestamps, version, tags, metadata, and typed `EntryData`. The current variants are `Credential`, `SSHKey`, `TOTP`, `Binary`, and `Netrc`. Each variant carries the fields needed for its operations.

The serializer uses `rmp_serde::to_vec`, which encodes structs positionally. The entry bytes are encrypted with a fresh random DEK. The entry blob includes that DEK wrapped under the vault KEK. See [ADR-003](ADR-003.md) for vault framing and [ADR-008](ADR-008.md) for key roles.

## Compatibility

The typed reader only supports known variants. The types have no storage for unknown fields. Even when the decoder accepts extra input, rewriting the decoded value can discard data the reader did not represent. Positional fields also make ordering part of the wire format.

Future field and variant changes require a compatibility decision and explicit version or migration tests before clients are allowed to rewrite them. Until then, use readers and writers that support the entry schema in use.

## Implementation

[`entries/types.rs`](../../crates/padlock-core/src/entries/types.rs) defines the schema. [`entries/serialize.rs`](../../crates/padlock-core/src/entries/serialize.rs) implements MessagePack serialization.
