# ADR-008 — Key hierarchy and passphrase change

## Status

Accepted. This describes the current vault lifecycle.

## Key hierarchy

1. Argon2id derives a passphrase-derived key (PDK) from the passphrase, the vault salt, and the selected KDF parameters.
2. HKDF derives separate KEK and MACKEY outputs from the PDK. The KEK wraps entry keys. The MACKEY authenticates the serialized vault.
3. Entry encryption generates a fresh random DEK. It encrypts the entry with XChaCha20-Poly1305 and stores the wrapped DEK and both nonces in that entry blob.

Optional recovery stores a recovery-key-wrapped copy of KEK and MACKEY in the header. Passphrase unlock derives those keys directly.

## Passphrase change

The operation starts with an unlocked vault. It derives a new PDK, KEK, and MACKEY using a fresh salt and the selected KDF parameters. It compacts deleted entries, decrypts each live entry with the old hierarchy, and encrypts the entry again with a fresh DEK wrapped under the new KEK. It updates the index offsets, invalidates recovery, and writes the new vault with a new HMAC. Recovery must be re-enabled explicitly.

Cost includes the new Argon2id derivation and work linear in the entry data processed and rewritten. Live entry ciphertext changes. Previously saved snapshots remain subject to their original unlock material.

## Future work

Format or cryptographic algorithm upgrades require a versioned migration and compatibility tests. Hardware-backed key custody is a separate design decision.
