# ADR-007 — Audit logging

## Current implementation

The core JSON Lines backend appends unsigned records and skips malformed lines when reading. The CLI `padlock audit` displays and filters `audit.jsonl` beside the selected vault. CLI vault operations do not automatically write audit events. The CLI has no `audit verify` command and this log provides no tamper detection, completeness, or compliance guarantee.

## Planned authenticated logging

Authenticated audit logging remains a design direction. An ordered chain should authenticate the stream identity, epoch, sequence, previous tag, and event bytes. The signer trust boundary, writer coverage, key custody, and durable append behavior require separate implementation and review.

A valid chain can detect altered or missing middle records given a trusted key and intact authentication. Deleting a suffix can leave a valid shorter chain. Truncation and rollback detection require a separately trusted fresh checkpoint with the expected stream, epoch, sequence and tail MAC. A checkpoint restored alongside the log cannot establish freshness. Offline chain verification can report the surviving chain and its anchored prefix, with any unanchored tail provisional.

## Implementation

[`audit/mod.rs`](../../crates/padlock-core/src/audit/mod.rs) implements unsigned JSON Lines. [`commands/audit.rs`](../../crates/padlock-cli/src/commands/audit.rs) implements the CLI viewer.
